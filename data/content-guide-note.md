# 書き方のルール（note）

目的：読んだ人が「おっ、この記事おもしろい。このアカウントをフォローしたい」と思う記事にする。
note の原稿を書くとき（scripts/note-run.py → scripts/note-prompt.md）は、毎回
data/content-guide.md の「共通の土台」（X 担当と共通・ファイルが無いときはこの下の控え）と、この「note のルール」を読み込む。
書き手の体験として書いてよい本当のことは data/note-facts.md だけ。

## note のルール
### タイトル
- 15〜25字。何の話か、誰向けかが一目で分かること。
- 例：「献立に悩む毎日を、AIに半分任せてみた」「洗濯の『干す』をやめたら朝が変わった」

### 見出し画像
- さわやかなサムネイルの型（1280×670・丸ゴシック・シリーズ名と番号）を毎回使う（scripts/note_design.py が自動で作る）。

### 本文の組み立て
1. 書き出し3行：読者の「あるある」に共感 → この記事で分かることを一言
2. 本文：見出しで区切り、1段落は3〜4行まで。必要なところは箇条書き
3. 書き手の体験や気づきを最低1か所入れる（元飲食店経営者の視点など、本当のことだけ＝data/note-facts.md にあることだけ）
4. まとめ：今日から1つだけ試せること
5. 次回予告：「次は ② 洗濯 の話です」のように、シリーズの続きを示す（番号と内容は note-run.py が渡す。決まっていない内容は約束しない）
6. 最後に問いかけ：「あなたの家の一番の面倒は何ですか？コメントで教えてください」
7. ブログの記事へのリンク（今まで通り）

### ハッシュタグ
- 毎回3〜5個：中身に合うもの（#献立 #時短家事 #家計簿 など）＋人が集まる大きめのもの（#暮らし #家事 #仕事効率化 など）。コンテストのタグは使わない。

### マガジン
- 「面倒を減らすシリーズ」と「小さな商売のつくり方」の2つ（data/note-magazines.json）。投稿のたびにシリーズのマガジンへ自動で追加する（note-run.py）。

## 共通の土台（控え：data/content-guide.md が無いときだけ使う）
- 「誰が書いても同じ一般論」は書かない。この発信者にしか書けない材料を使う：
  - 元飲食店経営者としての実体験（閉店後の締め作業、シフト、電話予約など）
  - 実際に作ったもの（住宅点検のカルテ発行・見積、飲食店のレジ・モバイルオーダー、問い合わせ受付）
  - 自動化ランキングの調査データ（何位か、なぜ面倒か）
- 数字は本物だけ。作り話の事例・お客さんの声は書かない。お客さんが特定できる情報は出さない。
- 誇張・断定・煽り（「必ず」「誰でも」「月◯万円」）は使わない。
- このアカウント自体が自動で動いていることに触れない。
