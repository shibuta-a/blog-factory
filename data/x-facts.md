# X の投稿で「実際にあったこと」として書いてよい話

X の文章だけの投稿（特に「作る途中でつまずいた話」）は、ここに書いてあることだけを実話として使う。ここにない出来事・数字・お客さんの声は作らない。
新しい実話ができたら、ここに足す（足すのは実際にあったことだけ）。

## 自社で作ったもの（jidouka-ranking.json の根拠「自社の実例」と同じ範囲）
- 見積書: 数量を入れると金額が出る見積の仕組み。建設・リフォーム向けには、数量を入れると複数プランの見積が同時にできるもの
- 飲食店のレジ締めと日計表: 閉店後に手で集計していた作業を、売上の自動集計に置きかえる考え方（運営者は飲食店を経営していた）
- 飲食店の注文取り: 卓上QRのモバイルオーダー
- 入居者からの問い合わせ: QRの受付フォームと電話の自動応答で、記録まで残す
- 物件の点検と報告書: スマホで点検して報告書PDFを発行する
- 現場写真の整理: 撮るときに部位を選ぶと台帳に並ぶ
- 点検カルテ・診断書: スマホ入力からカルテを作る
- 記念品・名入れギフト: デザインエディタで名前と写真を入れるだけで仕上がる仕組み（オリシャン。数字は data/orishan-facts.md の範囲だけ）

## 仕組みを作る途中でつまずいたこと（実話）
- Web サイトで、存在しないページを開いたときに「見つかりません」ではなくトップページが正常として返っていた。404 用のページを用意して直した
- あるサービスの管理画面が、ブラウザを閉じるとログインが消える作りだった。毎回入り直す前提で組み直した
- 投稿が終わったかどうかを画面の表示で判定していたら、お祝いのポップアップが出たときに「失敗」と判定してしまった。公開されたかを別の方法で確かめるように変えた
- Windows でファイルを書き出すと、改行コードが勝手に変わってしまい、差分が全部の行に出た。改行コードを指定して書くように直した
- 決まった時刻に動かすはずの処理が、時刻どおりに動かない日があった。「時刻が来たかどうかを、見に来たときに判定する」作りに変えた
- 写真を自動で選ぶ仕組みで、検索条件をゆるくすると内容に合わない写真が混じった。使う写真の出どころを絞った

## 書き方の注意

- 日付・回数・かかった時間などの数字は、ここに書いていなければ書かない
