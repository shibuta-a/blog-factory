# note の記事で「書き手の本当のこと」として書いてよい話

note の原稿では、書き手の体験・気づきとして、ここに書いてあることだけを使う。ここにない出来事・数字・お客さんの声は作らない。
新しい本当のことができたら、ここに足す（足すのは実際にあったことだけ）。

## 書き手
- 飲食店を経営していた。いまは、仕事の「毎回の面倒」を減らす仕組み（見積・点検・受付など）を作っている

## 飲食店をやっていた頃の面倒（題材としてだけ。細かい出来事・回数・時間は書かない）
- 閉店後の締め作業（レジ締め・日計表の集計を手でやっていた）
- スタッフのシフトづくり
- 電話での予約の受け付け

## 実際に作ったもの
- 見積書: 数量を入れると金額が出る見積の仕組み。建設・リフォーム向けには、数量を入れると複数プランの見積が同時にできるもの
- 飲食店のレジ締めと日計表: 閉店後に手で集計していた作業を、売上の自動集計に置きかえる考え方
- 飲食店の注文取り: 卓上QRのモバイルオーダー
- 問い合わせ受付: QRの受付フォームと電話の自動応答で、記録まで残す
- 住宅・物件の点検: スマホで点検して報告書PDFやカルテを発行する
- 現場写真の整理: 撮るときに部位を選ぶと台帳に並ぶ
- 記念品・名入れギフト: デザインエディタで名前と写真を入れるだけで仕上がる仕組み（オリシャン。数字は data/orishan-facts.md の範囲だけ）

## 調査データ
- 自動化ランキング（data/jidouka-ranking.json）: 困りごとの「順位」「今のやり方」「なぜ面倒か（困っている人の多さ・自動化のしやすさ）」は、そこに書いてあるとおりに引いてよい

## 書き方の注意
- この note やブログ、SNS が自動で動いていることには触れない
- 日付・回数・かかった時間・売上などの数字は、ここに書いていなければ書かない
- お客さん・取引先が特定できることは書かない
