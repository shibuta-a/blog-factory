# ブログ工場 公開済み記事の見直し（Claude Code がこの手順で動く）

あなたはブログ工場（C:\blog-factory）の記事見直し担当です。渋田さんへの確認は不要です。下の手順を上から順に、すべて自分で実行してください。
目的は、公開済みの記事を**読者にとって本当に良くする**ことです。Google は中身が良くなった記事を評価します。

## 絶対の決まり

- **中身を良くしていないのに更新日だけ新しくするのは禁止**（Google にスパム扱いされ、逆効果になる）。
  フロントマターの `updated` は自分で書かない。`refresh-done` が本文の変更量を確かめて、実質的な改善のときだけ自動で付ける
- 直す所がなければ、無理に直さない。`refresh-skip` で記録して終わってよい
- 各社の料金・日数・割引・ランキングなどの具体的な数字や順位を本文に書かない（比較表は台帳から自動で入る）。
  相場は「〜が目安です」「詳しくは公式サイトでご確認ください」と書く
- 「絶対」「No.1」「最安」「業界初」などの断定・誇大表現は使わない。PR表記・写真・比較表・申込みボタンは自動で入るので本文に書かない
- トーンは丁寧な「です・ます」調。煽らない

## 1. 見直す記事を決める

1. `python scripts/autopilot.py refresh-next` を実行する
   - 「見直しません」「見直す記事がありません」「本以上になったら」と出たら、**何もせずにそこで終わる**
2. 表示された記事のファイルを読む。`data/affiliates.json`（提携中の広告の台帳）と、同じジャンルの型（`templates/kata/` の該当ファイル）も読む

## 2. 次の観点で確かめる

- **★ 優先の見直し（目的）が表示されたら、まずそれを行う**:
  - 「閲覧数が多い記事」→ 読まれている記事なので、テーマに合う提携中の広告のうち**報酬の目安が高いもの**を優先して置く
    （本文の印 `<!-- AFFILIATE: 案件名 -->` の記事は、その節の印を報酬の高い合う案件に替えるか足す。`affiliates:` で指定している記事はそこを並べ替える。
    指定のない記事はビルドが自動で報酬の高い順に並べるので、本文はそのままでよい）
  - 「新しく承認された広告」→ その広告が読者に合う節があれば、その節に `<!-- AFFILIATE: 案件名 -->` を足す（`affiliates:` の記事はそこにも足す）
  - どちらも、**テーマに合わない広告は入れない**（報酬が高くても入れない）。広告を足すために本文の中身を誇張しない
  - 合う広告がなければ何もしないで `refresh-skip` してよい（優先の印はそれで消える）

- **古い情報はないか**: サービスの終了・名称変更、提携が終わった広告名が本文に残っていないか（台帳にない会社名を本文で勧めていないか）
- **新しく提携した広告**: このジャンルで台帳に新しく入った会社があり、記事の読者に合うなら、本文の比較の観点や選び方の説明に自然に触れる。
  フロントマターに `affiliates:` で広告を指定している記事は、そこにも足す
- **比較の選択肢**: 比較表・選び方の節に、読者が迷いそうな新しい観点・選択肢を足せないか
- **分かりやすさ**: 長すぎる段落、説明不足の用語、答えが曖昧なQ&A、読者の悩みに答えきれていない所はないか。Q&A は3問以上あるか

## 3. 直す（直す所があるときだけ）

1. 記事のファイルを編集する（`updated` は書かない）
2. `python scripts/autopilot.py refresh-done <slug> "<何をどう良くしたかを1行で>"`
   - 「更新日を…にしました」と出たら → `python scripts/publish.py -m "refresh: <slug>"` で公開する
   - 「実質的な改善とは言えない」と出たら → 誤字修正など小さな修正なので、そのまま `python scripts/publish.py -m "fix: <slug>"` で公開してよい（更新日は変わらない）

直す所がなかったときは `python scripts/autopilot.py refresh-skip <slug> "<確かめた結果を1行で>"` を実行し、
`python scripts/publish.py -m "refresh-check: <slug>"` で記録を保存する。

## 4. 記録

1. `python scripts/autopilot.py status`（STATUS.md に見直しの履歴が出る）
2. 最後に、見直した記事・直した内容（または直さなかった理由）を2〜4行で報告して終わる
