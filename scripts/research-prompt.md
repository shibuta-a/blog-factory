# 自動化記事の下調べ（前の日の実行の最後に、Claude Code がこの手順で動く）

あなたはブログ工場（C:\blog-factory）の下調べ担当です。渋田さんへの確認は不要です。記事は書きません。

## やること

1. `python scripts/autopilot.py jidouka-research-next` を実行する。「下調べが必要な回はありません」と出たら、何もせずに終わる
2. 表示された回の3つの困りごとについて、「道具の例」に合う代表的な道具・サービスを困りごとごとに2〜4個選び、
   WebSearch で**公式サイト**を探し、WebFetch で公式サイトのページを開いて確かめる。「提携中の広告」に出た案件があれば、その公式サイトも確かめる
3. 確かめた結果を、表示された保存先（`data/jidouka-research/<回>.md`）に下の形で保存する（このファイル以外は作らない・変えない）
4. 「保存しました」とだけ報告して終わる

## 確かめ方のルール

- 書いてよいのは**公式サイト（運営会社のサイト）に書いてあること**だけ。比較サイト・ブログ・まとめ記事・口コミは根拠にしない
- 料金は公式サイトに書いてある金額と条件（税込/税抜・月額/年額・無料プランの有無）をそのまま写す。分からなければ「公式サイトで確認できず」と書く
- 「No.1」「シェア」「◯％削減」などの宣伝の数字は写さない（記事でも使わない）
- 公式サイトが見つからない・開けない道具は、保存しない（「確認できず」の一覧にだけ名前を書く）

## 保存する形

```
# 第<回>回 下調べ（確認日: YYYY-MM-DD）

## 1. <困りごと>

### <道具・サービスの名前>
- 公式サイト: <URL>
- 何ができるか: <公式サイトに書いてある機能を2〜4個。短く>
- 料金: <公式サイトの表記どおり。分からなければ「公式サイトで確認できず」>
- 無料で試せるか: <無料プラン・無料期間の有無。分からなければ「公式サイトで確認できず」>
- 向いている人: <公式サイトの説明から分かる範囲で1行>

（道具ごとにくり返す）

## 2. <困りごと>
…

## 確認できなかった道具
- <名前>: <理由（公式サイトが見つからない など）>
```
